# ExamCue

ExamCue 是 Windows 優先、local-first 的桌面課堂考點分析器。它能一次匯入多個
YouTube 連結或本機影音檔，直接解碼音訊、建立含時間戳的逐字稿，再將內容整理為：

- **明示考點**：老師直接表示「會考」、「考試會問」或指定答案。
- **推論考點**：老師沒有直接說會考，但因重複強調、比較、例題或標準答案而可能重要。
- **易錯／警告**：老師明確提醒的陷阱、常見錯誤或容易混淆處。
- **排除範圍**：老師明確說不考、不用證明、不用背或僅供參考。

每個結果都包含來源影片、時間範圍、逐字證據、判定理由及可信度。明示與推論會分開
標示；逐字稿永遠視為待分析資料，不會被當成程式指令。

```text
YouTube／本機影音
        ↓
人工字幕 → YouTube 自動字幕 → 音訊（依序備援）
        ↓
字幕解析或 Faster-Whisper 批次辨識
        ↓
教材術語提示＋定時擷取課程畫面（選用）
        ↓
LLM 語意判斷（失敗時使用保守規則式備援）
        ↓
分組結果頁＋四選一題庫＋report.md＋report.json
```

## 功能

- 五步驟 Windows 圖形介面：加入來源、調整設定、開始分析、查看結果、練習選擇題
- 設定與 YouTube 連結輸入採主視窗內頁切換，不另外開啟自訂彈出視窗；儲存、完成或
  取消後回到原本頁面；每個管理頁左上角都有固定顯示的「← 返回」
- 本機影音也使用主視窗內的影音管理頁，可一次選取或拖放多個影音檔，並在完成加入前
  逐項移除或清空
- 可匯入 PDF、PPTX、TXT 或 Markdown 投影片／教科書；系統會抽取專有名詞提供給
  Whisper，並只挑選與當前逐字稿相關的教材段落輔助 LLM 理解；支援從檔案總管一次
  拖放多個教材到主視窗內的教材管理頁。可搜尋教材內容最多保留 120,000 字元，每次
  LLM 請求仍只加入最相關的 2,500 字元，兼顧多份教材覆蓋率與分析速度
- 可設定每 1、2、3、5、10 或 15 分鐘擷取一次課程影片畫面；不依賴 OpenCV，畫面會
  保存在專案 `frames` 資料夾，支援圖片的 LLM 可進一步描述投影片、公式與板書
- 可依已驗證的考點自動產生四選一題目、答案、解析與來源時間戳，輸出 `quiz.md`、
  `quiz.json`，並顯示於第五個頁籤
- 支援淺色／深色主題，包含原生 Windows 標題列
- 右上角齒輪設定可調整逐字稿分段、主題與分析完成後的介面行為，偏好會自動保存
- 設定頁會檢查 NVIDIA GPU、CUDA 12 cuBLAS 與 cuDNN 9，並可載入目前選擇的 Whisper
  模型執行真實 GPU 推論測試；缺少元件時直接顯示修復方式
- YouTube 連結採逐列輸入，完成一列會自動產生下一個空白列並提供完成按鈕
- 播放清單會在加入時先展開為個別影片網址，所有影片會逐列顯示於「待分析來源」
- 待分析來源會編號並以獨立列顯示；游標移到來源列時，可從右側紅色叉叉移除該項目
- 支援 YouTube 影片／播放清單，以及 MP4、MKV、MOV、AVI、WebM、MP3、M4A、WAV、AAC、FLAC、OGG
- YouTube 人工字幕、自動字幕優先；沒有可用字幕時才下載音訊並使用 Faster-Whisper
- 已完成的 YouTube 媒體資訊、字幕與音訊會重用，重跑時不再重複查詢或下載
- 必須下載 YouTube 音訊時，優先使用適合語音辨識的 128 kbps 以下音軌，沒有符合格式
  才回退至最佳音訊，減少大型播放清單的網路與磁碟成本
- 可選「自動字幕優先」或「強制 Whisper」，並提供快速、標準、精準三種辨識模式
- 本機影音直接交給 Faster-Whisper／PyAV 解碼，不先轉成大型 WAV，減少等待與磁碟用量
- 下載下一個來源會與目前來源的語音辨識重疊執行
- 自動偵測課程語言，支援混合語言，報告語言可自行指定；中文課程會以繁體中文提示重新
  辨識，避免繁簡混雜
- 語音辨識完成後立即釋放 Whisper 的 GPU 記憶體，避免與 LM Studio 搶顯示記憶體而讓
  畫面理解極度變慢
- 專案名稱與輸出資料夾末層名稱雙向同步；瀏覽視窗從目前路徑開啟
- 本機 LLM：自動偵測 LM Studio 或 Ollama 的 OpenAI-compatible API
- 外部 LLM：內建 OpenAI、OpenRouter，亦可連接其他 OpenAI-compatible API
- 內建 LLM 相容性測試，同時驗證模型清單、JSON 格式與實際考點判斷
- LLM 逾時或失敗時使用保守規則式備援，不以單一「重點」關鍵字猜測推論考點
- 預設完整掃描逐字稿，讓 LLM 判斷沒有固定關鍵字的考點；亦可切換提示優先以縮短時間
- 教材只在匯入或檔案變更後解析一次並建立專案索引，不會把整份教材送進每次請求；
  每段分析只附上最多約 1,200 字元的相關原文
- 教材不再預設成為 Whisper 的全域提示詞，避免專有詞表反過來造成重複或幻覺；教材
  主要用於 LLM 理解術語與語境，老師的逐字稿仍是考點的唯一證據
- LLM 使用精簡欄位、每次最多回傳五項並限制 512 個輸出 token；每個成功片段會立即建立
  續跑快取
- LLM 採精確優先判定：只有直接提及考試才列為明示；「重要」只能列為推論；「不講」
  不等同「不考」。一般例子、比較或定義若沒有考試訊號或強烈強調，不會單獨產生考點
- 送入 LLM 前會略過明顯的 ASR 重複迴圈；模型結果還會經過逐字引用、分類依據與訊號
  一致性驗證，降低技術名詞誤辨造成的假考點
- 先完成全部語音辨識，再進行考點分析；兩階段各占總進度 50%
- 分析中可暫停、繼續或取消
- 結果依四種分類顯示為彩色側欄群組，分類只顯示一次並垂直置中
- 每個結果標示 `LLM 判斷`、`規則式分析` 或 `規則式備援`
- 輸出 Markdown、JSON 與 JSONL 逐字稿
- 語音模型感知的逐字稿快取、分析快取與逐檔失敗隔離
- 保留未來 speaker diarization 與掃描式教材 OCR 接口

## 系統需求

- Windows 10 或 11
- Python 3.11 或更新版本
- 約數 GB 的可用磁碟空間；實際需求依影片及語音模型大小而異
- 首次使用 Faster-Whisper 時需連網下載語音模型
- 處理 YouTube 或使用外部 LLM 時需要網路連線

NVIDIA GPU 與 CUDA 並非必要。ExamCue 只會在 CUDA 12 cuBLAS 執行環境完整時使用
GPU；偵測到 GPU 但缺少必要 DLL 時會自動改用 CPU。

一般支援格式由套件內的 PyAV 直接解碼，因此目前不再要求先安裝 FFmpeg 命令列程式。

## 安裝

在 PowerShell 進入專案資料夾後執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

安裝腳本會建立 `.venv` 並安裝 ExamCue 與開發工具。完成後可雙擊
`run_examcue.bat`，或在 PowerShell 執行：

```powershell
.\.venv\Scripts\Activate.ps1
python -m examcue
```

若要手動安裝：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m examcue
```

若 Windows 電腦有 NVIDIA GPU，建議另外安裝官方 Python CUDA 執行庫，讓
Faster-Whisper 使用 GPU／float16：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_cuda.ps1
```

等價的手動指令為：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[cuda-windows]"
```

這個選用套件體積較大，因此不會在一般安裝時強制下載。安裝完成後必須重新啟動
ExamCue，讓程式載入新增的 DLL。

## 基本操作

1. 在「加入來源」頁按「加入影音檔」，會切換到同一主視窗內的影音管理頁；可一次選取
   多個檔案，或把多個支援的影音檔從 Windows 檔案總管拖到大型拖放區，再逐項移除、
   清空或按「完成加入」。按「加入 YouTube 連結」後，每個網址使用獨立單行欄位；
   貼上一筆後程式會自動增加下一個空白欄位，輸入完畢按右下角「完成」。
   YouTube 輸入會在同一個主視窗內切換，完成或取消後回到來源頁，不會另外產生視窗。
   影音、YouTube、教材與設定頁左上角皆有「← 返回」，不必先捲動到頁面底部。
   播放清單展開成功後會直接顯示為待分析來源列，不另外跳出成功視窗。若有投影片或
   教科書，按「加入投影片／教材」後會在同一個主視窗切換到教材管理頁；可在該頁一次
   選取多檔，或把多個 PDF、PPTX、TXT、MD 從 Windows 檔案總管拖到大型拖放區，並在
   按下「完成」前移除、清空或繼續追加；按左上角「返回」也會保存目前清單。這些教材只用來
   校正術語與補充上下文，不會單獨被當作「老師說會考」的證據。
2. 在「調整分析設定」頁指定專案名稱、輸出資料夾、報告語言、Faster-Whisper 模型、
   轉錄來源及辨識模式。專案名稱會與輸出資料夾的末層名稱保持一致；「瀏覽」會從欄位
   中的目前路徑開始。需要 LLM 時，先勾選「使用 LLM 分析」才會展開連線設定，填寫後可按
   「測試 LLM 分析」確認模型清單、JSON 輸出與實際考點判斷是否可用。V2 區域可調整
   影片畫面擷取間隔、是否分析畫面、是否產生題庫及最多題數。測試會要求模型
   從一段明確的 `This definition will be on the exam.` 文字產生考點，而不只是回覆 `OK`。外接服務的測試
   請求可能產生極少量 API token 費用。成功結果會直接顯示在 LLM 設定區，不另外跳出
   成功視窗。
3. 到「開始課程分析」頁確認摘要並按「開始分析」。頁面會顯示目前處理階段和進度條；
   開始後同一按鈕會變成「暫停」，暫停後可按「繼續」恢復。單一來源失敗不會中斷
   其他來源。
4. 完成後程式會切換至「查看分析結果」，可檢視摘要或按「開啟完整報告」。第五頁
   「練習選擇題」會顯示題目、答案、解析與對應影片時間。

### V2 畫面與教材注意事項

- 這裡的「擷取目前影像」是指從已加入的課程影片依時間軸取幀，不會監看或截取使用者
  的 Windows 桌面。
- 本機影片直接取幀；YouTube 在啟用功能時會另外下載最高 480p 的低解析度影像串流，
  因此會增加下載時間與磁碟使用量。
- 畫面理解需要支援圖片的多模態模型。LM Studio 會優先使用原生 `/api/v1/chat` 的
  `reasoning=off` 與 image input；其他服務使用 OpenAI-compatible `image_url`。文字模型
  不支援圖片時，ExamCue 會保留取幀圖片、記錄警告，並繼續完成轉錄、考點與題庫流程。
- 相似畫面會先以感知雜湊去重，再以每批最多四張送入模型；成功描述（包括確認為沒有
  可讀教學內容的畫面）會依圖片、模型與輸出語言快取，重跑不再耗用視覺模型時間。
- 掃描式 PDF（每頁只有圖片、沒有文字層）目前無法抽出教材文字；後續版本適合加入
  本機 OCR。一般文字型 PDF 與 PPTX 可直接使用。
- 為避免長教材拖慢本機 LLM，ExamCue 不會把整本教材重複送入每個請求；每個逐字稿
  片段只會檢索最多約 2,500 字元的相關教材內容。

結果頁依「明示考點、推論考點、易錯／警告、明確排除範圍」分組。每個分類只在左側
色帶顯示一次並垂直置中，右側每筆結果以分隔線與交錯底色呈現；將滑鼠移到結果區域
即可使用滾輪瀏覽，不會顯示固定捲軸。

主視窗右上角可隨時切換淺色或深色主題；旁邊的齒輪按鈕可開啟應用程式設定。
設定會覆蓋主視窗內容，按「儲存設定」或「取消」後回到先前畫面。
主題會套用到來源清單、設定卡片、結果表格，以及之後開啟的 YouTube 連結視窗。
來源、結果與 YouTube 連結列不顯示固定捲軸，將滑鼠移到對應區域後可使用滾輪捲動。
處理流程會先完成所有來源的轉錄，再開始考點分析；轉錄目前來源時，背景會預先準備
下一個來源。進度條的 `0–50%` 代表轉錄，Whisper 模式會依已處理的音訊時間更新；
`50–100%` 代表考點分析進度，並依全部影片實際候選文字量加權，不再假設每部影片耗時
相同。

齒輪設定的「語音辨識加速檢測」會先做環境檢查：確認 CTranslate2 看得到 NVIDIA GPU，
並能載入 `cublas64_12.dll` 與 `cudnn64_9.dll`。環境通過後可按「測試 GPU 語音辨識」，
程式會用目前在分析設定選擇的 Whisper 模型跑一秒合成音訊。只有這個實際測試成功，
才能證明模型推論確實可在 CUDA／float16 上執行；首次測試尚未下載過的模型時需要網路
且會等候模型下載。沒有 NVIDIA GPU 的電腦不需安裝上述套件，程式會正常使用 CPU／int8。
若正式分析採用 YouTube／人工字幕或命中既有逐字稿快取，本來就不會啟動 Whisper；只有
需要重新語音辨識的來源才會使用 GPU。

齒輪設定中的逐字稿分段模式會決定每次送給 LLM 的上下文大小：

| 模式 | 最長時間 | 最大字元 | 適合情況 |
| --- | ---: | ---: | --- |
| 精細 | 60 秒 | 2,000 | 考點密集、希望定位更精準，但 LLM 請求較多 |
| 標準 | 120 秒 | 4,000 | 建議預設，兼顧上下文與速度 |
| 長篇 | 240 秒 | 8,000 | 長段落與跨段說明，請先確認模型有足夠上下文 |

完整掃描時，每個片段只要先達到時間或字元上限，就會開始下一段。重點優先時，程式會
先保留提示句前後的短上下文；每個連續視窗仍遵守秒數與字元限制，最多再把三個互不相連
的短視窗合併成一個請求，以免 27B 等大型模型反覆處理只有數百字的零碎請求。增加片段
大小不會改變 Whisper 逐字稿內容，但會改變 LLM 每次看到的上下文、請求數量與 token
用量。切換模式後，分析快取會自動失效並重新分析。

若要在不呼叫 LLM、也不產生 API 費用的情況下估算某個既有專案需要多少次請求，可執行：

```powershell
.\.venv\Scripts\python.exe .\scripts\benchmark_analysis.py .\projects\test4
```

輸出會比較三種分段模式在「完整掃描」與「重點優先」下的預計呼叫次數、輸入字元數及
減少比例。以目前 `test4` 的 6 份逐字稿為例，標準模式由 142 次完整掃描降為 20 次
候選請求，呼叫數減少 85.9%，送入字元由 62,951 降為 9,535，減少 84.9%。這是離線
估算，實際時間仍取決於模型與硬體。

同一個設定區也能選擇掃描策略：

- **完整掃描（預設，品質優先）**：每個逐字稿片段都送給 LLM。適合不同科目與不同
  授課表達方式，也較能發現沒有固定提示詞的隱含考點；代價是耗時與 token 用量較高。
- **提示優先（速度優先）**：先用本機規則找出含「會考、不考、小心、注意、重要、重點、
  答案、差別」等訊號，擷取前 20 秒、後 40 秒範圍內的鄰近逐字稿，再合併最多三個短
  視窗送給 LLM。對老師會明確提示重點的課程速度提升最大，也能減少把一般技術敘述
  誤判成考點，但可能漏掉沒有固定關鍵字的內容。

匯入教材後，ExamCue 會在專案的 `cache/reference-index.json` 建立可重用索引。後續重跑
只要教材檔案沒有改變，就直接載入索引；每個逐字稿片段會以混合語言詞彙檢索少量相關
教材。沒有匹配內容時不會為了填滿上下文而加入無關教材。這種做法不依賴課名、章節編號
或特定語言，適合上下文較短的本機模型。

轉錄來源建議保留「自動」，程式會依序嘗試人工字幕、YouTube 自動字幕，兩者都沒有才
執行 Whisper。語音模型預設為 `large-v3`，辨識模式建議先用「標準」。`small` 對中文、
特別是中英夾雜的技術課程錯字明顯偏多，會連帶讓 LLM 判斷失準，只建議在沒有 GPU 或
需要極快速度時使用。大量影片可切換「快速」，需要更高辨識品質再選「精準」。第一次
執行模型下載會較久（`large-v3` 約 3 GB）。逐字稿快取會記錄語音模型、辨識模式及字幕
種類，切換後會重新轉錄。

偵測到中文課程時，ExamCue 會以「以下是繁體中文的課堂講解。」作為 Whisper 的提示重新
辨識，避免繁簡混雜並補上標點。這段提示刻意不含任何課程專屬詞彙；實測加入專有名詞反而
可能讓開頭整段被略過。英文等其他語言不受影響。語音辨識階段結束後，Whisper 模型會立即
從 GPU 釋放，讓後續的畫面理解與 LLM 分析有足夠的顯示記憶體。

三種辨識模式如下：

| 模式 | Beam | Batch | 取向 |
| --- | ---: | ---: | --- |
| 快速 | 1 | 8 | 大量影片，速度優先，使用較多記憶體 |
| 標準 | 3 | 4 | 建議預設，兼顧速度與品質 |
| 精準 | 5 | 1 | 品質優先，速度最慢、記憶體壓力較低 |

若要在自己的電腦上比較 Faster-Whisper 設定，可只分析某個媒體檔前 180 秒，不會改動
專案報告或快取：

```powershell
.\.venv\Scripts\python.exe .\scripts\benchmark_transcription.py `
  .\projects\test4\media\youtube-mC3MOlqY1Tg\audio.wav `
  --model small --seconds 180 --device cpu --compute-type int8 `
  --batch-size 8 --beam-size 1
```

輸出的 `realtime_factor` 越低越快。本次測試環境中，CPU 的 `small + fast` 處理 180 秒
約需 6.85 秒，`small + standard` 約需 7.28 秒；安裝 CUDA 執行庫後，同一台 RTX 4070
以 `small + standard + float16` 的 GPU 推論約需 1.29 秒（另有媒體解碼時間）。這只代表
該檔案與該電腦的測量結果。

### 建議組合

- 語音辨識：Faster-Whisper `large-v3`（預設）
- 考點分析：**27B 左右或更大的模型**，例如 `qwen/qwen3.8-27b`
- 推理設定：`No Thinking`（或關閉 `Enable Thinking`）；`Preserve Thinking` 建議關閉

建議使用大模型的原因：以一部 44 分鐘的中文電腦視覺課程實測 `qwen/qwen3.5-9b`，在逐字稿
已改用 `large-v3` 的情況下，人工標記約 17 個應抓考點中只抓到約 9 個，並出現以下問題：

- 同一份逐字稿重跑，抓到的考點不同（例如「這個很重要」「只考到這裡」時有時無）。
- 分類錯誤，例如把「考試不考申論、都用選擇題」標成排除範圍，或把一般定義標成明示考點。
- 標題與老師原意相反，或把語音辨識錯字直接寫進標題。

這些屬於小模型的語意判斷能力限制，換用較強的模型通常能明顯改善。12 GB 顯示卡無法把
27B 模型完整放進 GPU，LM Studio 會把部分層放在 CPU 執行，速度會明顯變慢；若硬體有限，
可改用外部 API 的大模型，或接受 9B 模型較低的召回率。

> `Preserve Thinking` 只控制是否保留先前的推理內容，並不等於關閉 Thinking。
> ExamCue 對本機 LM Studio 會使用原生 `/api/v1/chat` API 並設定
> `reasoning: off`；其他本機 Qwen 相容端點則會要求非思考模式，避免輸出額度全被
> `reasoning_content` 用完而沒有正式 JSON 答案。LLM 連線測試也只有在收到
> 正式答案時才會成功；若報告顯示「規則式備援」，代表該次結果不是 LLM 判斷。

這是目前測試環境的經驗值，不是硬性需求。實際速度仍會受到 CPU／GPU、記憶體、影片
長度、逐字稿語言及本機 LLM server 設定影響；其他 OpenAI-compatible 模型也可使用。
完整掃描大量影片時，27B 模型的生成速度可能成為主要瓶頸。若優先考量速度，可先試用
同系列或能力相近的 7B～14B 指令模型，確認它能穩定輸出 JSON，再比較考點召回率與
誤判率；切換到另一個 26B 左右的模型通常不會帶來明顯的速度級距改善。

## LLM 設定

### 本機自動偵測

選擇「本機自動偵測（LM Studio／Ollama）」即可。ExamCue 依序嘗試：

- `http://localhost:1234/v1`（LM Studio）
- `http://localhost:11434/v1`（Ollama）

請先在對應軟體載入模型並啟動 OpenAI-compatible server。「LLM Model」留白時會使用
`/models` 回傳的第一個模型；也可以填入確切 model ID。API Key 通常可留白。

正式分析預設會把逐字稿切成最長約 2 分鐘或 4,000 字元的片段，也可從齒輪設定改成
60 秒／2,000 字元或 240 秒／8,000 字元。單次 LLM 請求最多等待 300 秒，以支援速度
較慢的本機大型模型。完整掃描會逐段交給 LLM；每段最多要求五個有獨立證據的考點、
使用精簡 JSON 欄位並限制為 512 個輸出 token，避免本機模型花大量時間生成
冗長說明。若 LLM 連續兩個片段失敗，本次剩餘內容會自動熔斷並改用保守規則，避免每一
段都等待逾時。失敗片段只保留明示考點、警告及排除範圍，不會用「重點」等單一關鍵字
猜測推論考點。報告與結果表的「分析方式」會標示 `LLM 判斷`、`規則式分析` 或
`規則式備援`。

### OpenAI

1. 選擇「OpenAI」。Endpoint 會設為 `https://api.openai.com/v1`。
2. 在「LLM Model」填入帳號目前可用的 model ID。
3. 在「API Key」貼上金鑰。

### OpenRouter

1. 選擇「OpenRouter」。Endpoint 會設為 `https://openrouter.ai/api/v1`。
2. 在「LLM Model」填入 OpenRouter 顯示的完整 model ID。
3. 輸入 OpenRouter API Key。

### 其他外部或自架服務

選擇「自訂 OpenAI-compatible API」，填入 base URL（通常以 `/v1` 結尾）、model ID
及需要的 API Key。服務至少必須相容以下端點：

- `GET /models`
- `POST /chat/completions`

目前驗證方式是 `Authorization: Bearer <API Key>`。需要 Azure `api-key` header、原生
Anthropic Messages API 或其他非相容協定的服務，需另加 adapter；現版本不能直接連接。

若不勾選「使用 LLM 分析」，ExamCue 會使用規則式分析。若已勾選但 LLM 無法連線、
逾時或回傳格式無效，則對失敗片段使用保守規則式備援。保守備援只保留明確的
「會考／不考／小心」等直接語句，不會產生推論考點，以避免報告被關鍵字誤判淹沒。
備援會擷取訊號附近的短原句並排除考試比喻、過往考試故事、面試與分數閒談，不再把
整段冗長逐字稿直接當成標題。若 LLM 把兩段真實引文用省略號連接，ExamCue 會先確認
每個片段都存在於指定的逐字稿區段，再從原文重建單一連續證據；無法獲得原文支持的
改寫或幻覺內容仍會被拒絕。

## 輸出結構

每次分析會在指定資料夾建立：

```text
project/
  media/          # YouTube 字幕／原始音訊／媒體資訊快取；本機影音不會被複製或轉檔
  transcripts/    # 每段含時間戳的 JSONL 逐字稿
  frames/         # 依設定間隔擷取的課程畫面
  cache/          # 逐字稿、考點、畫面描述與題庫快取
  report.json     # 結構化完整結果
  report.md       # 適合閱讀的報告
  quiz.json       # 結構化選擇題、答案、解析與來源
  quiz.md         # 適合閱讀的選擇題題庫
  run_metrics.json # 最近一次執行的模型、影片長度、各階段耗時與快取統計
  run_history.jsonl # 每次執行的效能歷史紀錄，每行一筆 JSON
```

`run_metrics.json` 會記錄媒體與轉錄、考點分析、報告產生時間，各來源影片長度與耗時，
以及每個來源實際使用的轉錄裝置、compute type、Beam 與 Batch，
以及實際 LLM endpoint/model、請求數、請求總時間、分析片段數、片段快取命中與失敗數。
其中 `quality_filtered_segment_count` 是分析前略過的異常重複逐字稿數，
`quality_rejected_cue_count` 是 LLM 回傳後未通過證據閘門的候選數。
`empty_direct_response_count` 則表示模型面對明確考試／警告訊號仍沒有產生可用結果的
次數；這類空白片段會各自使用保守規則式備援，但 ExamCue 仍會繼續把後續候選片段交給
LLM，避免較小模型前段漏判後使整份報告停止語意分析。只有連線、逾時或格式錯誤等真正
的請求失敗連續發生兩次時，才會熔斷後續 LLM 呼叫。
所有固定的 LLM system/user 指令與相容性測試內容都使用英文；實際逐字稿可以是任何語言，
模型輸出語言則只由 GUI 的「報告語言」設定決定，不固定為繁體中文。
API Key 不會寫入效能紀錄。即使執行取消或失敗，也會留下狀態與已完成的計時資料；
`run_history.jsonl` 可用來比較不同模型與掃描策略的長期速度。

### 15 部影片壓力測試（2026-10-20）

以 README 範例播放清單的 15 部公開影片測試，逐字稿總長約 40,492 秒（11.25 小時），
設定為 `small + fast`、Qwen3.5-9B、重點優先掃描、每 5 分鐘取幀、教材提示與最多 15 題：

- 播放清單正確展開 15 部影片，擷取 142 張畫面；感知去重後只需送出 98 張。
- 修正後多模態模型成功描述 142/142 張（相似畫面共用描述），考點輸出 48 筆，並只對
  能由單一考點支持的內容產生 3 題，避免為湊題數而臆造答案。
- 媒體與逐字稿已有快取、但新版畫面與考點需重新分析時，完整 pipeline 約 255 秒；
  畫面理解是主要耗時。加入畫面與題庫快取後，全部命中的 pipeline 約 2.24 秒，連同
  播放清單展開約 2.9 秒。
- 同一批影片的舊版基準約 2,959 秒（49 分 19 秒）。首次下載與 Whisper 轉錄仍取決於
  網路、GPU、字幕可用性與模型；`run_history.jsonl` 保留每次實測，避免只看估算值。

小型模型速度快，但對口語化或辨識品質不佳的明確訊號可能保守拒答；此時報告會誠實
標示「規則式備援」。若更在意考點語意品質而非速度，建議改用較強模型，並比較
`empty_direct_response_count`、`non_llm_chunk_count` 與總耗時，而不是只比較考點數量。

更換 Whisper 模型、轉錄來源或辨識模式會讓逐字稿與分析快取失效；更換逐字稿分段、
掃描策略、報告語言、LLM endpoint 或 model 也會讓完整分析快取失效。LLM 的 system
prompt 內容也包含在片段快取指紋中，因此更新分析指令後不會沿用舊的空白結果。加入中文
提示前產生的 Whisper 逐字稿，會在下一次分析時自動重新辨識一次。成功完成的 LLM
片段會立即寫入 `cache/analysis-chunks/`，即使稍後取消或某段失敗，重跑時也能跳過已完成
片段。API Key 不會寫入快取、報告或設定檔，也不會
被納入快取指紋。`report.md` 與 `report.json` 會記錄各來源使用人工字幕、自動字幕或
Whisper。

## 隱私與費用

- 使用本機 LLM 時，影音與逐字稿可留在本機；YouTube 下載及首次語音模型下載仍會連網。
- 使用外部 LLM 時，逐字稿片段會傳送給所選服務商，並可能產生 API 費用。使用前請確認
  服務條款、資料保留政策及學校規範。
- GUI 中的 API Key 僅保留於目前程式記憶體；關閉程式後不保存。請勿把金鑰提交到 Git。
- YouTube 內容的下載與使用仍須遵守平台條款及著作權規範。

## 常見問題

### 本機影片為什麼沒有先抽成 WAV

Faster-Whisper 使用 PyAV，可直接解碼 MP4、WebM、M4A 等支援格式。預先轉成 WAV 會多做
一次完整影音讀取，還會產生很大的暫存檔，因此新版直接讀取原始檔。舊專案若已有
`audio.wav` 快取仍可繼續使用。

### LLM 無法連線，改用備援

依序檢查 server 是否已啟動、Endpoint 是否包含正確的 `/v1`、model ID 是否正確、API
Key 是否有效，以及防火牆或代理伺服器是否阻擋連線。本機服務可先在瀏覽器或
PowerShell 測試 `<endpoint>/models`。

### LLM 測試成功，但正式分析仍然逾時

連線測試只送出極短提示，因此成功不代表長逐字稿一定能在相同時間內完成。ExamCue
目前預設先篩選並合併候選上下文，再以最多 384 個輸出 token 要求精簡 JSON；模型只需回傳短
證據與判斷依據代碼，易讀的完整理由由 ExamCue 組合。單次正式請求最多
等待 300 秒；連續失敗兩次後會停止繼續呼叫 LLM。若本機
模型仍逾時，可關閉 Thinking、改用較小或較快的模型，或降低本機 server 的負載。
逾時片段會清楚標示警告並使用保守規則式備援。

### YouTube 下載失敗

YouTube 可能暫時拒絕某個媒體串流網址，即使公開影片也可能回傳 HTTP 403。ExamCue 會
重新取得串流網址並自動嘗試最多 3 次。播放清單內若只有個別影片持續失敗，程式會跳過
該影片、保留其他已成功下載的項目，並在完成時列出影片編號、標題與錯誤原因。

若同一影片持續失敗，可稍後重試，並先在已啟用虛擬環境的 PowerShell 執行：

```powershell
python -m pip install --upgrade yt-dlp
```

私人、付費、地區限制、需要登入，或 YouTube 要求額外 PO Token 的影片不一定能處理。

### 顯示 `cublas64_12.dll`、CUDA 或 cuDNN 錯誤

這代表 NVIDIA GPU 可被偵測，但 CUDA 執行環境不完整。
ExamCue 會在啟動模型前檢查 CUDA 12 cuBLAS 與 cuDNN 9，若不完整便使用 CPU；執行途中遇到 CUDA
函式庫錯誤也會自動以 CPU 重試。CPU 速度較慢，但不需要另外安裝 CUDA。

有 NVIDIA GPU 時可關閉 ExamCue，執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_cuda.ps1
```

重新啟動後，開啟右上角齒輪，先按「重新檢測環境」，再按「測試 GPU 語音辨識」。若環境
檢測成功但實際測試失敗，通常是顯示卡驅動過舊、顯示記憶體不足，或 GPU 同時載入了
大型 LLM；請先更新 NVIDIA 驅動、釋放顯示記憶體，或改用較小的 Whisper 模型。

### 結果太少或推論不準

依序檢查：

1. **LLM 模型大小**：9B 等小模型常漏判、分錯類或寫錯標題，建議改用 27B 左右或更大的
   模型（見「建議組合」）。
2. **逐字稿品質**：打開 `transcripts/*.jsonl` 確認內容。語音模型請用 `large-v3`；專有
   名詞仍常被誤辨（例如 Covariance、Flood Fill、灰階值），而錯字會同時誤導 LLM 與規則
   判斷。
3. **報告中的分析方式**：若大量標示「規則式備援」，代表 LLM 對那些片段沒有產生可用結果。

ExamCue 刻意避免把每一句技術內容都誤判為考點，因此證據不足時會傾向不輸出。
